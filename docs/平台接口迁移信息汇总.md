## 四、认证与签名要点（迁移风险）

平台 Step1 仅提供：**无认证 / Basic Auth / OAuth 2.0**。本项目实际鉴权如下，需与平台方确认是否支持「自定义签名插件 / 前置脚本」。

### 4.1 旺店通奇门（双签名）

1. 系统参数放在 URL Query：`app_key`、`method`、`timestamp`、`sign`、`target_app_key` 等  
2. 业务参数放在 Body（form）：`params`、`pager`、`wdt_sign` 等  
3. 签名：
   - `wdt_sign`：旺店通业务签名（`app_secret`）
   - `sign`：淘宝奇门 TOP 签名（`qimen_appsecret`）

配置字段：`app_key` / `app_secret` / `qimen_appkey` / `qimen_appsecret` / `target_appkey` / `wdt3_customer_id`

### 4.2 慧经营（hjySign + 奇门）

1. 业务侧：`appId`、`sid`、业务参数 + `hjySign`  
2. `hjySign` = MD5(排序后 `key:value&...` + `hjy_app_key`)  
3. 外层仍走奇门系统参数与 TOP `sign`

配置字段：`hjy_app_id` / `hjy_sid` / `hjy_app_key` / `hjy_gateway_url`

### 4.3 OpenAPI（单 MD5）

`sign = MD5(secret + 排序键值拼接 + secret)`，Body 为 JSON。

### 4.4 微伴 / 微信

先换 token，再带 `access_token` 调业务接口；接近平台「OAuth 2.0 / Token」能力，优先尝试平台原生认证。

## 五、平台录入建议（按网关拆分，而不是按 method 硬拆 30+ 条）

若平台「源接口地址」只能填一个 URL，且不支持按 `method` 路由，有两种落地方式：

| 方案 | 做法 | 适用 |
|------|------|------|
| A. 按网关建 3～5 个代理透传 | 奇门 / 慧经营 / OpenAPI / 微伴 / 微信各建一条，下游用 method 或 path 分流 | 适合先快速打通 |
| B. 每个 method / path 建一条 API | 源地址仍是网关，在基本信息里用 method 名区分 | 适合精细治理、限流、监控 |

**推荐**：先用 **方案 A 打通连通性**，再按业务优先级用方案 B 细化（订单/售后/账单优先）。
